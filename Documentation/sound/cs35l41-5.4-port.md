# Cepheus CS35L41 port to the 5.4 kernel

## Scope and verified baseline

Target: `JoK3rLeE/android_kernel_xiaomi_5.4`, branch `5.4-port`.

Hardware reference: Xiaomi's Cepheus Qualcomm audio-kernel source at
`MiCode/vendor_qcom_opensource_audio-kernel`, branch `cepheus-q-oss`,
`asoc/codecs/cs35l41/`.

This is an active porting record. The current branch is not yet a completed or buildable CS35L41 port.
Do not enable the driver in a device build until the source conversion and
board-specific route have been validated.

## DSP architecture

There are two separate DSP domains and they must not be conflated:

* Qualcomm QDSP6/AFE/ADM/ASM is the SoC audio path. Keep the target kernel's
  existing QDSP6 implementation and machine/card routing.
* CS35L41 contains its own Cirrus Halo DSP. The host accesses registers and
  loads amp firmware through I2C/regmap; PCM and telemetry use the amp's ASP
  serial audio interface. The Cirrus DSP firmware and speaker-protection
  controls belong to the CS35L41 driver, not to Qualcomm QDSP6.

Do not replace QDSP6 with wm_adsp, or attempt to load the Cirrus firmware into
the Qualcomm DSP.

## Confirmed 4.14-to-5.4 incompatibilities

The Xiaomi vendor driver is based on the legacy ASoC codec API. Source audit
found these old interfaces in `cs35l41.c`:

* `snd_soc_codec_get_drvdata` (15 uses)
* `snd_soc_kcontrol_codec` (5 uses)
* `snd_soc_dapm_to_codec` (3 uses)
* `dai->codec` (4 uses; plus one `codec_dai->codec`)
* `snd_soc_codec_get_dapm`
* `struct snd_soc_codec_driver` and `snd_soc_register_codec`
* `wm_adsp2_codec_probe/remove`
* `wm_halo_early_event/event` and `wm_halo_set_clocking`

The target 5.4 `wm_adsp.h` already exposes the component-based API:
`wm_adsp2_component_probe/remove`, `wm_adsp_event`,
`wm_adsp_early_event`, `wm_adsp2_set_dspclk`, and `wm_halo_init`.
It also has CS35L41 rate-control compatibility fields. Therefore, keep the
target's WM ADSP implementation as the base; do not copy the legacy vendor
`wm_adsp.c/h` over it and create duplicate DSP implementations.

## Required source conversion

1. Convert codec-private access to `snd_soc_component_get_drvdata()`.
2. Convert DAPM context lookups to `snd_soc_dapm_to_component()` and component
   DAPM accessors.
3. Replace codec-driver registration with a component driver plus the codec
   DAI declaration/registration model available in this 5.4 tree.
4. Convert DSP event sequencing carefully. The vendor code has separate
   `halo_booted` state and calls the legacy Halo events; map these to target
   WM ADSP events only after comparing their state transitions. Do not simply
   rename event functions.
5. Reconcile DSP firmware naming, `wmfw` parsing, algorithm controls, RX/TX
   rate-control fields, mailbox handling, watchdog/bus-error IRQ paths, and
   preload behavior between the vendor and target `wm_adsp.c`.
6. Keep Xiaomi-specific `linux/mfd/spk-id.h` / speaker-identification
   behavior only if the Cepheus board path actually supplies and consumes it.
7. Port I2C probe/remove, regulators, reset/IRQ handling and regmap tables;
   ensure all error paths unwind power and DSP resources safely.

## Board-specific validation required before enabling

The existence of a generic CS35L41 driver is not sufficient. Verify from the
Cepheus DTS, machine/card driver and vendor configuration:

* actual I2C bus/address and compatible string;
* speaker-identification GPIO / speaker type selection;
* VA/VP supply names and sequencing;
* reset GPIO, IRQ polarity/source and interrupt masks;
* ASP format, clock master/slave role, BCLK/LRCLK rates, channel slots and
  telemetry TX slots;
* DSP firmware filenames and the userspace/vendor firmware delivery path;
* amp DAPM widgets/routes and the QDSP6/AFE-to-ASP route.

Do not copy Raphael's channel slots, clock master settings, GPIOs, or boost
configuration without proving they match Cepheus.

## Current status (2026-10-20)

Verified on `5.4-port`: `include/sound/cs35l41.h` exists, and the target has a
component-oriented `wm_adsp.h`, but `sound/soc/codecs` contains no CS35L41
implementation. The Xiaomi Cepheus source is under
`MiCode/vendor_qcom_opensource_audio-kernel/cepheus-q-oss/asoc/codecs/cs35l41/`.
It includes separate I2C/SPI frontends, codec/DSP implementation, register
tables, and vendor Kbuild/Kconfig; it is not a single source file that can be
safely copied into the target tree.

**Port is incomplete and must remain disabled.** The earlier `CONFIG_SND_SOC_CS35L41=y`
entry was premature because no matching Kconfig symbol or driver exists in the
5.4 tree; it has been removed to avoid advertising an enabled-but-unbuildable
configuration. Remaining work: port the source set, convert the legacy ASoC
codec API and DSP event lifecycle to the target API, integrate Kconfig/Makefile,
validate actual Cepheus amp nodes/routes/firmware, and run compile/link and
hardware tests. No runtime success is claimed.
